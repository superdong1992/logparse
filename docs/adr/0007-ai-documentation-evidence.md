# ADR-0007：面向代理的阅读入口与产品日志规格

- Status: Accepted
- Date: 2026-10-12
- 实现核对基线：`0ad92ff`

## 背景与授权

ADR-0006 的精简已统一解析链路。仓库仍缺少按任务查阅的入口，以及把产品配置、日志字段、处理规则和验证证据连起来的说明。

所有者于 2026-10-12 明确要求实施《基于最新代码调整 GLM5.2 文档方案》：新增两份文档，完善现有架构说明与导航，清理两处陈旧文档字符串，记录已知限制并执行交付验证。本 ADR 记录这次文档变更的具体授权，不扩大 ADR-0006，也不授权今后的任意架构修改。

## 决策

- 新增 `docs/ai-reading-guide.md`，提供任务阅读路径、证据要求和固定核对题。
- 新增 `docs/product-log-specification.md`，描述当前实现支持的日志规格、两套产品的支持矩阵、合成样例和已知限制。
- 完善 `docs/architecture.md`，作为唯一的仓库结构与调用链说明；不另建重复的代码仓说明书。
- README、CLAUDE 和使用说明链接到上述入口；代码改动仅限配置服务和产品模型的陈旧文档字符串。
- 每项关键结论关联配置、实现或已有测试。区分合成验证、真实 LAN 验收和模型回答评估，不把未执行项写成通过。
- compact 文件名日期解析及诊断技能缺少产品参数的问题只记录为独立待办，不在本轮修复。

CLI/API、配置格式、产物 schema、生命周期与关联算法、诊断技能输入契约均保持不变。独立 logparse 继续保持确定性，不增加模型调用或文档自动生成服务。

## 验证与回滚

核对文档路径、符号、命令、配置和合成样例，运行聚焦测试、`scripts/verify_delivery.py`、规则预检与强制变更门禁。GLM5.2 的核对题提供参考答案和证据；实际模型评估需要在已配置该模型的 LAN 会话中执行，未执行时如实记录。

验证记录位于 `governance/changes/2026-10-12-ai-reading-docs.yaml`。回滚只移除本轮新增文档与导航段落，并还原两处文档字符串；保留其他改动，不回退 ADR-0006 的实现。未经另行明确授权，不提交、推送或外传材料。
