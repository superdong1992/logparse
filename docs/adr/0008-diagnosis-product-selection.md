# ADR-0008：诊断预处理显式选择产品

- Status: Accepted
- Date: 2026-10-12

## 背景与授权

`parse` 根据 `--product` 选择根配置 `products` 下的产品，省略时使用 `default`。现有诊断技能及生成模板只传递配置路径，可能让其他产品的原始日志使用错误配置。

所有者已明确选择“原始输入必须明确产品”，要求只修复诊断技能漏传产品参数，并授权执行该计划。本 ADR 仅覆盖技能输入与交接说明、生成模板、契约校验、对应测试和文档，不沿用 ADR-0006 作为任意变更的授权。

## 决策

- 原始输入必须提供 `product`，其值对应完整根配置 `products` 下的键。沿用用户已明确的产品；缺失时先询问，不推断或默认为 `default`。
- `config_path` 仍须指向包含具体 YAML 文件名的完整根配置，不能将被 include 的产品片段直接传给 `-c`。
- 生成技能将 `product` 作为运行时输入，与其他解析设置交给 `logparse-diagnose`；所有完整 parse 示例显式传入 `--product <product>`。不把产品固定在 frontmatter。
- 已有 `result.json` 时复用结果，不为补产品参数重新解析。后续目标查询不需要新增产品参数。
- 校验器分别检查产品输入声明、交接清单和预处理命令；只在其他位置提及产品不能替代这些要求。
- CLI 默认行为、配置及产物 schema、生命周期与关联算法保持不变。文件名日期解析不在本次范围内。

## 验证与回滚

运行生成技能契约测试，覆盖缺少输入、交接字段和命令参数的拒绝场景；检查规范技能及参考文档的命令。将现有 CLI 闭环测试扩展为显式选择两套仓内产品配置，并运行完整交付验证、规则预检和强制门禁。

黄色路径只修改技能参数交接，不改变生命周期或关联业务规则。使用仓内合成样例回归，没有真实 LAN case，真实历史 corpus 未执行；不得写成真实产品验收。
